# Ссылочная модель Java. Идентичность и равенство

В главе про память мы разобрали, что объекты живут в куче, а переменные хранят ссылки на них. Теперь разберём, что из этого следует для сравнения объектов: чем идентичность отличается от равенства, как правильно переопределять `equals` и `hashCode` и зачем это нужно.


## 1. Ссылка и объект

Переменная ссылочного типа хранит не сам объект, а ссылку на него. Присваивание копирует ссылку, а не объект:

```java
Point a = new Point(3.0, 4.0);
Point b = a;          // b ссылается на тот же объект, что и a
```

Теперь `a` и `b` — две переменные, указывающие на один объект. Изменение через `a` видно через `b`. Чтобы получить независимую копию, нужно создать новый объект и скопировать значения полей.

Как объекты устроены в памяти и как они передаются в методы, разобрано в главе про память — [20_memory.md](20_memory.md).


## 2. Идентичность и равенство

Два понятия легко спутать.

Идентичность (identity) — две ссылки указывают на один и тот же объект. Проверяется оператором `==`.

Равенство (equality) — объекты содержат одинаковые значения полей. Проверяется методом `equals`.

```java
Point a = new Point(3.0, 4.0);
Point b = new Point(3.0, 4.0);
Point c = a;

a == b;        // false — разные объекты
a == c;        // true — одна и та же ссылка
a.equals(b);   // зависит от того, переопределён ли equals
```

По умолчанию `equals` в классе `Object` работает как `==` — сравнивает ссылки. Чтобы сравнение шло по содержимому, `equals` переопределяют.


## 3. Контракт equals

Переопределяя `equals`, нужно соблюдать требования контракта:

- рефлексивность — `x.equals(x)` истинно;
- симметричность — `x.equals(y)` истинно тогда и только тогда, когда истинно `y.equals(x)`;
- транзитивность — если `x.equals(y)` и `y.equals(z)`, то `x.equals(z)`;
- согласованность — пока объекты не изменены, повторные вызовы дают один результат;
- `x.equals(null)` всегда `false`.

Правильный `equals` для класса `Point`:

```java
@Override
public boolean equals(Object o) {
    if (this == o) return true;                    // та же ссылка
    if (o == null || getClass() != o.getClass()) return false;
    Point p = (Point) o;
    return Double.compare(p.x, x) == 0 &&
           Double.compare(p.y, y) == 0;
}
```

Параметр имеет тип `Object`, а не `Point`: метод переопределяет `equals` из `Object`. Сначала проверяется ссылка, затем тип, затем поля. Для `double` используется `Double.compare`, а не `==`, — так корректно обрабатывается особое значение `NaN`.

В Python те же роли играют методы `__eq__` и `__hash__`; в C++ сравнение объектов задаётся оператором `==`, а хеширование — специализацией `std::hash`.


## 4. Контракт hashCode

`hashCode` возвращает целое число — свёртку содержимого объекта. Его используют структуры данных с хешированием: `HashMap`, `HashSet`.

Контракт простой: если объекты равны по `equals`, их `hashCode` обязаны совпадать. Обратное не требуется — разные объекты могут иметь одинаковый `hashCode` (это называется коллизией).

Если переопределить `equals` и забыть `hashCode`, `HashMap` сломается: объект положат в корзину по одному хешу, а искать будут по другому, и поиск не найдёт объект, хотя по `equals` он совпадает.

```java
@Override
public int hashCode() {
    return Objects.hash(x, y);
}
```

`Objects.hash` принимает значения полей и строит хеш по ним. Для `double` это работает корректно.


## 5. Переопределение toString

`toString` возвращает строковое представление объекта. Его вызывает `System.out.println` при выводе. По умолчанию `Object.toString` даёт «имя класса @ хеш» — обычно хочется что-то осмысленное:

```java
@Override
public String toString() {
    return "Point(" + x + ", " + y + ")";
}
```

Осмысленный `toString` полезен при отладке: объект можно вывести на печать и сразу увидеть его состояние.


## 6. Класс Object

У любого класса есть предок — `Object`. От него наследуются методы, которые можно переопределять:

| Метод | Назначение |
|---|---|
| `toString()` | строковое представление объекта |
| `equals(Object)` | сравнение по содержимому |
| `hashCode()` | хеш объекта |
| `getClass()` | класс объекта во время выполнения |

Есть и другие методы `Object` — `clone`, `finalize` (устарел), `wait`/`notify` (относятся к многопоточности, это отдельный курс). Для учебных классов важны первые четыре.


## 7. null и NullPointerException

Ссылка может не указывать ни на какой объект — тогда её значение `null`. Обращение к методу или полю по `null`-ссылке бросает `NullPointerException`:

```java
Point p = null;
p.distanceToOrigin();    // NullPointerException
```

Проверять ссылки на `null` перед использованием — обычная практика; для этого есть метод `Objects.requireNonNull`, который бросает исключение с понятным сообщением, если аргумент `null`. Подробнее об исключениях — в главе [15_exceptions.md](15_exceptions.md).


## Практические советы

- Переопределяйте `equals` и `hashCode` всегда вместе — иначе сломаются `HashMap` и `HashSet`.
- В `equals` сначала проверяйте ссылку (`this == o`), затем тип, затем поля; параметр — `Object`.
- `hashCode` стройте через `Objects.hash(...)` по тем же полям, что участвуют в `equals`.
- `toString` делайте осмысленным — он пригодится при отладке.
