# Классы и объекты в Java

В главе «Введение в ООП» мы разобрали, что такое класс, объект, поле и метод, и посмотрели на минимальный класс `Point`. Теперь разберём синтаксис объявления класса в Java подробно: модификаторы доступа, конструкторы, инициализацию полей и контроль постоянства.


## 1. Объявление класса

Класс объявляется ключевым словом `class`, за которым следует имя. Внутри фигурных скобок — поля, конструкторы и методы. Возьмём класс `Point` из главы про введение в ООП и разберём его по частям:

```java
class Point {
    double x;                    // поле — координата точки
    double y;

    Point(double x, double y) {  // конструктор
        this.x = x;
        this.y = y;
    }

    double distanceToOrigin() {  // метод
        return Math.sqrt(x * x + y * y);
    }
}
```

Поля `x` и `y` — переменные, объявленные внутри класса. Конструктор — метод с именем класса и без возвращаемого типа; он вызывается при создании объекта оператором `new` и задаёт начальные значения полей. Метод `distanceToOrigin` вычисляет расстояние от точки до начала координат.

Ключевое слово `this` — ссылка на текущий объект. В конструкторе параметры названы так же, как поля, и запись `this.x = x` означает «полю текущего объекта присвоить значение параметра». Без `this` компилятор не отличил бы поле от параметра.

| | C++ | Python | Java |
|---|---|---|---|
| Объявление класса | `class` или `struct` | `class` | `class` |
| Конструктор | имя класса | `__init__` | имя класса |
| Ссылка на текущий объект | `this` (указатель) | `self` (параметр) | `this` |
| Видимость по умолчанию | `private` в `class`, `public` в `struct` | всё открыто | package-private |

В C++ `this` — указатель, обращение через `->`; в Java `this` — ссылка, обращение через точку. В Python конструктор называется `__init__`, а ссылка на объект передаётся первым параметром `self`.


## 2. Модификаторы доступа

Доступ к членам класса регулируется модификаторами. В Java их четыре:

| Модификатор | Сам класс | Пакет | Подкласс в другом пакете | Все остальные |
|---|---|---|---|---|
| `private` | да | нет | нет | нет |
| без модификатора (package-private) | да | да | нет | нет |
| `protected` | да | да | да | нет |
| `public` | да | да | да | да |

Поля обычно объявляют закрытыми (`private`) — это принцип сокрытия: внешний код не может менять поля напрямую, только через методы класса. Это необходимо тогда, когда нужен контроль записываемых в поля данных.

Некоторые методы, которые нужны только внутри класса тоже можно делать закрытыми. 

`public` используют для полей и методов, которые должны быть доступны всем, и внутри и вне класса.

`protected` похож на `private`, но его используют когда нужно дать потомкам класса (производным классам) доступ к членам данного класса. 


В C++ есть `friend` — функция или класс, которым открыт доступ к закрытым членам. В Java такого механизма нет; частично его роль играет package-private доступ: члены без модификатора видны всем классам того же пакета. В Python закрытость — только соглашение: поля, начинающиеся с подчёркивания, принято не трогать извне, но язык не запрещает.


## 3. Инкапсуляция на практике

**Инкапсуляция** — принцип ООП, согласно которому класс должен объединять поля и методы для работы с этими полями. Для изменения значения полей и получения их значений создают сеттеры и геттеры соответственно.

Сеттер -- метод, который должен изменять значение поля на новое, задаваемое извне. Он проверяет предусловие -- требования к новому значению и не даёт записать некорректное значение в поле.

Геттер -- метод, который просто  возвращает значение поля ничего не изменяя.

К принципу инкапсуляции часто добавляют *принцип сокрытия*: поля должны быть закрыты для прямого доступа, доступ к ним должен осуществляться только через методы. Это строго гарантирует корректность значений в полях.


Класс `Seconds` из учебных примеров ([examples/java/simple-class](../../examples/java/simple-class)) — полный пример инкапсуляции:

```java
public class Seconds {
    private int s;

    public Seconds() {
        s = 0;
    }

    public Seconds(int s1) {
        setS(s1);
    }

    public int getS() {
        return s;
    }

    public void setS(int s1) {
        if (s1 >= 60 || s1 < 0) {
            throw new IllegalArgumentException("seconds must be in 0..59");
        }
        s = s1;
    }

    // увеличивает число секунд на 1, учитывает переполнение
    public int tick() {
        s = (s + 1) % 60;
        return s;
    }

    @Override
    public String toString() {
        return String.valueOf(s);
    }
}
```

Поле `s` закрыто. Прочитать его можно только через `getS`, изменить — только через `setS`, который проверяет предусловие и бросает исключение при некорректном значении. Конструктор с параметром тоже идёт через `setS`, поэтому объект не может появиться в некорректном состоянии. Метод `toString` возвращает строковое представление объекта — его вызывает `System.out.println` при выводе. Аннотация `@Override` над методом говорит компилятору, что этот метод переопределяет метод предка — здесь `toString` из класса `Object`; подробнее об этом в главе про наследование.

В полной версии класса из примера есть ещё два метода `add` — это перегрузка, о ней в разделе 4.


## 4. Конструкторы

Конструктор — метод, который вызывается при создании объекта и инициализирует объект (задаёт начальные значения полей). Имя конструктора совпадает с именем класса, возвращаемый тип не указывается.

Если в классе не объявлен ни один конструктор, компилятор создаёт конструктор по умолчанию — без параметров, который ничего не делает. Как только вы объявили любой конструктор, конструктор по умолчанию исчезает: `new Seconds()` перестанет компилироваться, если не объявить его явно.

У класса может быть несколько конструкторов с разными параметрами — это перегрузка (overloading). Компилятор выбирает нужный по типам аргументов:

```java
Seconds s1 = new Seconds();      // конструктор по умолчанию
Seconds s2 = new Seconds(42);    // конструктор с параметром
```

Конструктор с параметрами не должен допускать некорректных значений — он вызывает сеттеры, которые уже проверяют предусловия. Так сделано в `Seconds`: `Seconds(int s1)` вызывает `setS(s1)`.

Конструкторы могут вызывать друг друга через `this(...)` — тоже первой строкой. Это избавляет от дублирования:

```java
public Seconds() {
    this(0);        // вызов конструктора с параметром
}

public Seconds(int s1) {
    setS(s1);
}
```

В C++ есть конструкторы копирования и перемещения и деструкторы; в Java их нет. Объекты копируются присваиванием ссылок, а память освобождает сборщик мусора — глава про память [20_memory.md](20_memory.md). В Python конструктор — `__init__`, и вызвать другой конструктор из него так же просто, как в Java, нельзя.


## 5. Инициализация полей

Поля можно инициализировать тремя способами: значением по умолчанию, инициализатором и в конструкторе.

Значения по умолчанию. Если поле не инициализировано, оно получает значение по умолчанию: `0` для чисел, `false` для `boolean`, `null` для ссылок. Локальные переменные так не работают — их обязательно инициализировать до использования.

Инициализатор — значение, указанное прямо при объявлении поля:

```java
class Point {
    double x = 1.0;    // инициализатор
    double y = 1.0;
}
```

Инициализаторы выполняются до тела конструктора, в порядке объявления полей. Если инициализатор и конструктор задают одно поле, выигрывает конструктор — он выполняется позже. В C++ похожую роль играет список инициализации конструктора `: x(1.0), y(1.0)`.


## 6. Метод вместо избыточного поля

Не все характеристики объекта стоит хранить в полях. Если значение можно вычислить из остальных полей, хранить его отдельно — избыточность: при каждом изменении придётся пересчитывать поле, а согласованность значений держать вручную.

Классический пример — комплексное число. Модуль вычисляется из действительной и мнимой частей, поэтому хранить его полем не нужно:

```java
class ComplexNumber {
    private double real;    // действительная часть
    private double imag;    // мнимая часть

    ComplexNumber(double real, double imag) {
        this.real = real;
        this.imag = imag;
    }

    // модуль числа — метод, а не поле
    double mod() {
        return Math.sqrt(real * real + imag * imag);
    }
}
```

Если бы `mod` был полем, при изменении `real` или `imag` его пришлось бы пересчитывать вручную, а отдельное изменение самого поля следовало бы запретить. Метод решает обе проблемы.


## 7. Контроль постоянства и модификатор `final`

Модификатор `final` запрещает изменение.

- `final` поле — значение можно присвоить только один раз: в инициализаторе или в конструкторе. После этого изменить его нельзя.
- `final` метод — нельзя переопределить в подклассе; подробнее — в главе про наследование.
- `final` класс — от него нельзя наследоваться.

```java
class Circle {
    private final double radius;   // радиус задаётся один раз

    Circle(double radius) {
        this.radius = radius;
    }
}
```

В C++ похожую роль играет `const`. В Java `final` не делает объект неизменяемым — он запрещает менять только саму ссылку или поле. В Python аналога нет.


## Практические советы

- Поля объявляйте `private`, доступ открывайте геттерами и сеттерами.
- Сеттеры проверяют предусловия, конструкторы вызывают сеттеры — объект не должен появляться в некорректном состоянии.
- Не храните избыточные поля: вычисляемые значения делайте методами.
- Помечайте `final` поля, которые не должны меняться после создания объекта.
