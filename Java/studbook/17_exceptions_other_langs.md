# Обработка ошибок в C и современных языках

> Этот файл — дополнение к [15_exceptions.md](15_exceptions.md). Здесь собраны подходы к сигнализации об ошибках в C и альтернативные механики в Rust и других языках.

## Как сигнализировать об ошибке в C

- Вернуть код ошибки или специальное значение из функции
- Записать в параметр-указатель специальное значение
- Использовать специальную служебную переменную для сохранения кода ошибки


### 1. Возврат кода ошибки

```c
#include <stdio.h>
#include <stdlib.h>

/// Открывает файл и возвращает файловую переменную
/// Если файл не удалось открыть, то возвращает NULL
FILE *open_file(const char *path) {
    FILE *f = fopen(path, "r");
    if (!f) {
        perror("fopen");
        return NULL;         
    }
    return f;
}


int main(void) {
    FILE *f = open_file("data.txt");
    // Проверка исключительной ситуации 
    if (!f) {
        // Обработка исключительной ситуации
        fprintf(stderr, "Не удалось открыть файл\n");
        // ...
    }
    /* работа с файлом ... */
    fclose(f);
}
```

 

### 2. Параметр‑указатель для результата/ошибки

```c
#include <stdio.h>
#include <stdlib.h>

/// Читает первую строку из файла и записывает её в `out`
/// Возвращает 0 в случае успеха, -1 в случае ошибки
int read_first_line(const char *path, char *out, size_t out_len) {
    FILE *f = fopen(path, "r");
    if (!f) return -1;               // ошибка открытия
    if (!fgets(out, (int)out_len, f)) {
        fclose(f);
        return -1;                   // ошибка чтения
    }
    fclose(f);
    return 0;                        // успех
}



int main(void) {
    char line[256];
    if (read_first_line("data.txt", line, sizeof(line)) != 0) {
        fprintf(stderr, "Ошибка чтения файла\n");
    }
    printf("Первая строка: %s\n", line);
}
```

### 3. Специальный параметр-указатель на код ошибки (errno)

Некоторые функции C не возвращают код ошибки напрямую, а сигнализируют об ошибке через глобальную переменную `errno`, которая объявлена в `<errno.h>`.

```c
#include <stdio.h>
#include <math.h>
#include <errno.h>

int main(void) {
    errno = 0;               // сбрасываем перед вызовом
    double r = sqrt(-1.0);   // математически некорректно

    if (errno == EDOM) {     // Domain Error — аргумент вне области определения
        printf("Ошибка: sqrt от отрицательного числа (%f)\n", r);
        // r будет NaN, дальнейшие вычисления с ним бессмысленны
    }
}
```

`errno` — это «специальная переменная»: функция не возвращает значение ошибки, а *побочно* записывает его в глобальную область, а вызывающий код проверяет её после вызова.

- В C ошибки обычно сигнализируются через коды возврата или специальные параметры.
- В обоих случаях важно проверять результат сразу после вызова функции.


### Стандартные функции C, использующие разные способы сигнализации об ошибке

| Функция | Библиотека | Как сигнализирует об ошибке | Пример проверки |
| :--- | :--- | :--- | :--- |
| `fopen()` | `<stdio.h>` | Возвращает `NULL` | `if (!f) { /* ошибка */ }` |
| `malloc()` | `<stdlib.h>` | Возвращает `NULL` | `if (!ptr) { /* нехватка памяти */ }` |
| `read()` | `<unistd.h>` | Возвращает `-1`, код в `errno` | `if (n == -1) { perror("read"); }` |
| `sqrt()` | `<math.h>` | Устанавливает `errno` в `EDOM` | `if (errno == EDOM) { /* ... */ }` |
| `strtol()` | `<stdlib.h>` | Возвращает `0` или `LONG_MIN/MAX`, устанавливает `errno` в `ERANGE` | `if (errno == ERANGE) { /* переполнение */ }` |
| `printf()/scanf()` | `<stdio.h>` | Возвращают отрицательное число при ошибке | `if (printf(...) < 0) { /* ошибка вывода */ }` |

Обратите внимание: одна функция может сочетать оба подхода. Например, `read()` возвращает `-1` **и** дополнительно записывает конкретный код ошибки в `errno`. Универсального способа нет — каждую функцию нужно проверять по-своему.


### Сравнение C-подходов: преимущества и недостатки


**Код возврата** (`return NULL`, `return -1`, …) 

**Преимущества**
* Простота и очевидность. Результат проверяется сразу после вызова<br>
* Нет скрытого состояния (как у `errno`).
* Максимальная производительность.
    
**Недостатки**
- Занимает возвращаемое значение — нельзя вернуть и данные, и код ошибки одновременно
- Легко забыть проверить; компилятор не предупредит
- При глубокой вложенности нужно вручную пробрасывать код наверх

&nbsp;

#### Параметр-указатель

**Преимущества**
* Возвращаемое значение свободно для результата
* Явный: в сигнатуре видно, что есть «выходной» параметр

**Недостатки**
* Усложняет интерфейс функции (лишний параметр)
* Вызывающий код должен создать переменную и передать адрес
* Всё та же проблема: легко пропустить проверку


## Глобальная переменная (`errno` и др.) 

**Преимущества**
+ Не меняет сигнатуру функции (`sqrt(x)` без лишних параметров)
+ Даёт числовой код ошибки (можно различать причины) 

**Недостатки**
- *Глобальное состояние*. Вызов другой функции может перезаписать глобальную переменную до того, как вы его проверили − Требуется сбрасывать глобальную переменную  перед вызовом (`errno = 0`)
- Не потокобезопасна в классическом POSIX (в современных системах — TLS, но это скрытая сложность
- Проверка далеко от места ошибки


**Вывод для C.** Универсального решения нет. В библиотечных функциях комбинируют подходы: возврат «маркера» ошибки (NULL, -1) + детализация через `errno`. Главное правило: **всегда проверять результат сразу**, не допуская, чтобы между вызовом и проверкой выполнился другой потенциально ошибочный код.


## Современный подход: Result-тип (Rust)

Rust предлагает принципиально иной способ — тип `Result<T, E>` из стандартной библиотеки. Это **дискриминируемое объединение** (sum type), которое может находиться ровно в одном из двух состояний:

- `Ok(value)` — операция выполнена успешно, результат `value`;
- `Err(error)` — произошла ошибка, `error` содержит информацию о ней.

```rust
use std::fs::File;
use std::io::{Error, Read};

/// Читает первую строку из файла.
/// Возвращает Ok(String) при успехе, Err(Error) при ошибке.
fn read_first_line(path: &str) -> Result<String, Error> {
    let mut file = File::open(path)?;  // ? пробрасывает Err наверх
    let mut line = String::new();
    file.read_to_string(&mut line)?;
    Ok(line)
}

fn main() {
    match read_first_line("data.txt") {
        Ok(line) => println!("Первая строка: {}", line.trim()),
        Err(e)   => println!("Ошибка: {}", e),
    }
}
```

### Ключевые свойства Result-типа

1. **Типобезопасность.** Компилятор не даст использовать значение, если не обработана ветка `Err` (предупреждение `unused_must_use`).
2. **Нет скрытого потока управления.** В отличие от исключений, `Result` — обычное значение: его возврат и проверка видны в коде явно.
3. **Оператор `?`.** Сокращает «проброс» ошибки наверх: `expr?` разворачивает `Ok` и присваивает значение, а при `Err` — немедленно возвращает его из функции (аналог `throws` в Java, но на уровне типов).
4. **Производительность.** Нет накладных расходов на стек unwind (как у исключений).

### Result в сравнении с C и Java

| Характеристика | C (код возврата) | Java (исключения) | Rust (Result) |
| :--- | :--- | :--- | :--- |
| Компилятор проверяет обработку? | ❌ нет | ✅ для checked | ✅ всегда |
| Возвращаемое значение + ошибка? | ❌ (нужен out-параметр) | ✅ | ✅ |
| Проброс через уровни вызовов | ручной `if err → return` | автоматический (стек unwind) | оператор `?` |
| Производительность при ошибке | 🟢 | 🔴 (stack unwind) | 🟢 |
| Читаемость основного пути | низкая (проверки перемешаны с логикой) | высокая | высокая (с `?`) |

> **Важно:** Result-тип — не единственный современный подход. В Haskell и Scala есть `Either[L, R]`, в Swift — `throws` с `do-catch` (похож на Java, но без checked), в Go — множественный возврат `(result, error)`. Однако Rust — самый яркий представитель подхода «ошибка как значение» (error-as-value), сочетающий проверку компилятором с нулевыми накладными расходами.
